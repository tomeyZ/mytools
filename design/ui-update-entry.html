先看现状

顶栏右侧现在是 [v1.1.3] + [浅色|深色] 两组，中间隔 12px。 位置本身没问题 —— 主题是全局设置、版本是应用级信息，都属于「跟具体工具无关」的那一类，放最右端是 VS Code / Chrome 的通行做法，不用挪。 真正的问题是：v1.1.3 现在长得跟装饰性文字一模一样（12px、最浅的 --text-3、等宽字体、没有任何容器）， 所以你会觉得"它在那儿，但好像没什么用"。加上检查更新之后，它正好被救活。

A · 版本号本身变成入口推荐

把 v1.1.3 从 <span> 换成 <button>，点它就查更新。 不新增任何位置，右区仍然只有两组。版本号是"更新"天然的锚点 —— 人看到版本号，第一反应就是"我是不是最新的"。 下面四个小图只画右区（真实右区约 190px 宽），因为差异只在这里。

A1 低调型 · 常态 = 现在这样

外观与现状完全一致，不改任何视觉。但静态下看不出可点，只有鼠标划过才浮现描边 —— 用户很可能一直不知道它能点。内部工具，发现性比克制重要。

A2 明确型 · 常态就是小胶囊

跟左边搜索框同一种「浅底 + 细边」语言，一眼看出是控件。代价是右区多了一个有边界的方块，稍显热闹 —— 但只多 1px 描边，比 A1 的"隐形"划算。

A2 · hover 态

描边转 --accent、底色转 --surface，跟其他按钮的 hover 语言一致。

A2 · 检查中

图标位换成转圈、文字变「检查中…」，期间禁用点击防空转。 注意这里：文字一变长，胶囊就会撑宽，把右边的主题切换整体往左推。 建议给胶囊写死 min-width（按"检查中…"的宽度算），让右侧不跳。

A2 · 后台查到有新版本 （可选增强）

启动时静默查一次，有新版就在胶囊右上角点一个红点 —— 用户完全不用记得来点，看到红点自然会点。 代价是每次启动多一次后台请求（异步、不阻塞界面）。要不要做可以后面单独定。
