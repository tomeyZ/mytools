**需求**：用户要求默认进页面选中「代码视图」，且按钮顺序对调（代码视图在前、树视图在后）。

## 工具条按钮加内联 SVG 图标

**需求**：参考 bejson 截图给按钮加图标；用户明确要求**保留排序/去转义**（bejson 没有这俩，不删）。

**实现**（`frontend/src/components/JsonFormat.vue`）：
- 8 个按钮（代码视图/树视图/格式化/压缩/排序/去转义/转义/Unicode转中文）各加一个 Lucide 风格内联 SVG（14px，stroke）
- 关键点：`stroke="currentColor"` + `fill="none"`——图标颜色自动跟随文字（hover 蓝、激活白），不需要为每种状态写独立样式
- 语义配对：去转义=eraser（橡皮擦，擦掉转义符）、转义=quote（双引号图形，转义的核心对象）——初版用的 lock-open/lock 因意象偏「安全加密」被用户否掉，换成贴合文字处理的图形
- `.tool-btn` 改 `display:inline-flex; align-items:center; gap:5px`，`.btn-icon` 14px + `flex-shrink:0`
- padding 从 `5px 14px` 收到 `5px 12px` 平衡图标占位

**为什么不引图标库**：Element Plus 未引入、独立装 lucide-vue 增加依赖；内联 SVG 零依赖、构建产物几乎无增量、跟随主题色。后续要加按钮直接复制一个 `<svg class="btn-icon">` 即可。

## 错误横幅交互优化：空内容静默 + 5 秒自动消失

**需求**：① 空内容点功能按钮不报错、静默不动作；② 错误横幅几秒后自动消失。

**实现**（`frontend/src/components/JsonFormat.vue`）：
- 新增 `showError(msg)` / `clearError()` 统一入口：`showError` 设置消息后启动 5 秒（`ERROR_AUTO_DISMISS_MS`）计时器自动清空，重复报错重置计时；`clearError` 手动清空并取消计时器
- 6 个功能按钮（格式化/压缩/排序/去转义/转义/Unicode转中文）空内容分支改为静默 `return`，且**空值判断在 `clearError()` 之前**——空内容点击是真·无操作（连旧横幅都不动）
- 全部散落的 `error.value = xxx` 收敛到两个入口（grep `error\.value\s*=` 验证只剩 helper 内部赋值），注释声明禁止再直接赋值绕过计时器
- `onBeforeUnmount` 清理计时器，防组件销毁后定时器空跑

**注意的行为细节**：`onChange` 的实时校验也走 `showError`——持续输入非法 JSON 期间每次击键重置计时，横幅会一直显示；停止输入 5 秒后才消失。`unescapeAndFormat` 分支③依赖「先 `setText`（触发 onChange）后 `showError`」的赋值顺序保证特定提示不被覆盖，改动时别调换这两行的顺序。

## 移除树视图，只保留代码视图

**决策过程**：用户问树视图是否没用。分析后发现**代码视图（ace）本身就带 JSON 折叠**——`ace/mode/json` 有 `foldingRules`，`showFoldWidgets` 默认开启，行号悬停出现折叠箭头。当初引入树视图就是为了 bejson 式折叠，结果代码视图原生就有。树视图剩余独特价值（类型着色、节点级复制）用户用不上，决定移除。

**改动**（`frontend/src/components/JsonFormat.vue`，约 -70 行）：
- template：整个 `mode-switch` 按钮组 + `toolbar-divider` 删除
- options：`modes` 数组删除（无切换需求），`onModeChange` 回调删除，注释更新说明折叠在代码视图行号悬停可用
- script：`currentMode` ref、`switchMode` 函数、return 对应字段全删；`getEditorText` 注释订正（防御逻辑保留）
- CSS：`.mode-switch` ×4、`.tool-btn--active`、`.toolbar-divider` 规则删除

**教训**：引入功能前先查依赖库是否已原生提供同类能力——jsoneditor 的 code 模式一直有折叠，绕了一圈树视图是冗余的。

## 配置单一数据源：删除 internal/config/wails.json 副本

**背景**：项目里有两个 wails.json——根目录的是 Wails CLI 正式配置；`internal/config/wails.json` 是手动副本，因 `//go:embed` 只能嵌包内文件，被 config.go 嵌入提供运行时 name/version/author（窗口标题、版本检查 version.go）。双写隐患：升版本要改两处，忘改一边无任何报错。

**顺带发现死配置**：根 wails.json 的 `build.extra_files: ["wails.json"]` 把配置随产物打包，但 grep 全部 Go 代码确认没有任何地方从磁盘读它（运行时全走 embed）——已删。

**方案 A 落地**（用户确认后执行）：
- `main.go`：`//go:embed wails.json` + `var wailsConfig []byte`，传给 `config.Init(wailsConfig)`
- `internal/config/config.go`：删 embed 依赖，`Init(configData []byte)` 接收字节，`loadConfig` 内部化；加注释禁止再放副本
- 删除 `internal/config/wails.json`（internal/config/ 现在只剩 config.go）
- 根 `wails.json` 删 `build.extra_files` 死配置

**验证**：`go build ./...` + `go vet ./...` 通过。今后版本号只改根 `wails.json` 一处。

**通用教训**：`//go:embed` 嵌不了包外文件的正确解法是「在能嵌的包（如 main）嵌入后传值」，不是复制文件到包里。
